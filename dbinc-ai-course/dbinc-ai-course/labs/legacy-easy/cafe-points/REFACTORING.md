# 카페포인트 리팩토링 대상

`cafe.py`에서 리팩토링할 곳을 정리했어요. **동작은 바꾸지 않아요.** 같은 입력이면 콘솔 영수증, `out/members.csv`, `out/report.txt`가 글자 하나까지 같아야 해요. 버그 수정과 정책 변경(CAFE-1~5)은 이 작업에 넣지 않아요.

## 안전망: 바꾸기 전과 후 비교

테스트가 없으니 출력 비교가 유일한 확인 방법이에요. 단계마다 확인해요.

    # 리팩토링 전에 한 번
    python -X utf8 cafe.py > before.txt && cp -r out before_out
    # 단계마다
    python -X utf8 cafe.py > after.txt && diff before.txt after.txt && diff -r before_out out

지금 샘플 데이터로 실행한 기준값은 주문 6건, 매출 36800원, 적립 703점, VIP 2명이에요. 샘플에는 크리스마스 날짜, 잔액보다 많은 포인트 사용, 명부에 없는 회원 같은 경우가 없어요. 그래서 이런 주문을 넣은 비교용 데이터를 따로 만들어 두면 더 안전해요.

## 리팩토링 대상

위험이 낮은 것부터 순서대로 정리했어요. 한 단계마다 비교하고 커밋해요.

### 1. 안 쓰는 코드 지우기
- 주석 처리된 2019년 적립률 코드: 95-98
- 주석 처리된 디버그 print: 112
- 아무도 부르지 않는 함수: `run2()`(168), `load_members()`(28), `reset_points()`(49)
- `ADMIN_PASSWORD`(13): `reset_points`를 지우면 쓰는 곳이 없어져요. 다만 `web/src/App.tsx`에 같은 값이 있으니 키오스크 쪽은 이번 범위에서 빼요.

### 2. import 부작용 없애기
- 174번 줄 `run()`을 `if __name__ == "__main__":` 아래로 옮겨요. `python cafe.py`로 실행할 때는 그대로 동작하고, import만 할 때는 마감이 돌지 않게 돼요. 이게 있어야 나중에 함수 단위 테스트를 붙일 수 있어요.

### 3. 정책 숫자에 이름 붙이기
- 이름을 붙일 숫자: 적립률 0.01과 0.03(99-102, 125-128), VIP 기준 100000(108, 121, 134, 145, 162), 쿠폰 3000과 최소 주문 5000(91, 94, 115), 최소 사용량 1000(88), 크리스마스 날짜와 배수(103-104, 129-130)
- 영수증과 보고서 문구에 들어간 숫자("(일반 1%, VIP 3%)", "기준 누적 100000원" 등)도 상수에서 만들어요. 단, 출력 문자열은 전과 똑같아야 해요.
- CAFE-1~4를 나중에 처리할 때 이 상수만 바꾸면 되도록 하는 게 목적이에요.

### 4. 복사된 두 갈래 합치기
- 생일 갈래(91-122)와 일반 갈래(123-146)는 대부분 같은 코드예요. 실제로 다른 점은 세 가지뿐이에요.
  - 결제액에서 쿠폰 금액을 빼는지
  - 적립 기준 금액(`amt`인지 `gyeolje`인지)
  - 영수증의 쿠폰 줄
- 이 세 가지만 갈래별로 다르게 두고 나머지는 한 흐름으로 합쳐요. **적립 기준 금액의 차이(CAFE-5)는 유지해요.** 주석으로 표시해 두면 버그를 고칠 때 찾기 쉬워요.

### 5. 등급을 한 곳에서 다루기
- 지금은 `Grade` enum을 155번 줄에서만 쓰고, 나머지는 문자열 `"VIP"`와 비교해요(99, 109, 120, 125, 135, 144).
- 등급별 적립률을 표 하나로 만들고, 등급 비교는 `Grade`로 통일해요. CAFE-4(골드 등급)를 쉽게 추가하기 위한 준비예요.
- CSV에 저장되는 값(`"일반"`, `"VIP"`)은 그대로 둬요.

### 6. 이름 바꾸기와 전역 변수 없애기
- 로마자 이름을 영어로 바꿔요: `hoewon_bulleogi`, `maechul`, `gyeolje`, `jeoklip`, `jeoklip_hap`, `gunsu`, `sseun_kupon`, `tmp`, `mon`, `mid`
- 뜻이 안 보이는 한 글자 이름도 바꿔요: `m`, `a`, `o`, `r`, `f`, `v`, `k`
- 이름 규칙을 맞춰요: `saveMembers`(camelCase)를 snake_case로 바꿔요.
- 전역 변수 `maechul`(15, 59)은 `run()` 안의 지역 합계로 바꿔요. 한 번 실행하는 결과는 같아요.
- 파일을 닫을 때 `open`/`close`를 직접 쓰던 곳(20-25, 39-46, 61/147, 157-164)을 `with`로 바꿔요.

### 7. 계산과 출력 나누기
- 지금은 주문 하나를 계산하면서 바로 `print`해요. 이걸 "주문 하나를 계산해 결과를 돌려주는 함수"와 "결과로 영수증 문자열을 만드는 함수"로 나눠요.
- 마감 보고도 집계와 파일 쓰기를 나눠요.
- 그러면 계산 로직을 콘솔 출력 없이 테스트할 수 있어요.

### 8. `run()`을 작은 함수로 나누기
- 회원 불러오기 → 주문별 처리 → 회원 저장 → 보고서 쓰기 순서로 나눠요.

## 주의가 필요한 것 (동작에 영향이 갈 수 있음)

아래 두 가지는 정상 실행의 출력은 그대로지만, 실패하거나 시간이 걸리는 상황에서는 동작이 달라져요. 할지 말지 먼저 정하고 진행해요.

- **`except: pass` 제거(150-151):** 지금은 회원 저장이 실패해도 조용히 넘어가요. 없애면 실패할 때 오류로 멈춰요. 정상 실행 결과는 같아요.
- **`time.sleep(1)` 제거(152):** "지우지 마시오, 이유 모름"이라는 주석이 달려 있어요. 출력에는 영향이 없지만, 마감 스크립트를 이어서 돌리는 다른 프로그램이 이 1초에 기대고 있을 가능성은 확인하지 못했어요.
